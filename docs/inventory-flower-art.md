# Native dynamic flower artwork — Steam v3.0.1

The inventory flower art pipeline uses the original `FlowerItemDetails.PatternMasks`, not similarity, species-name matching, or a generic petal mask. `public/inventory-flower-art/index.json` maps the native Item ID, native pattern index and AssetReferenceSprite GUID to the exact Sprite path ID and original atlas render data. Twenty-five flower definitions have 161 distinct mask references, all resolved against the original `atlas_iconcolormasks` AssetBundle.m_Container GUID keys. Pattern index 0 in this mapping denotes the original null Pattern reference, not an editable flower pattern. No valid-option or entitlement claims are made.

Source hashes are pinned in the index. The original atlas Texture2D (CAB-4b1eea545f0ffab2c4bbd5e5b64d20b0, PathID 7743984056776833729) was decoded from BC3 and vertically oriented, then encoded at its original 2048×2048 size as VP8L method 6 with exact decoded RGBA readback. The WebP contains the source atlas, including ten non-flower masks; it is not fetched by the current inventory UI. No original UnityFS bundles are included.

Switch v3.0.1 type definitions identify `FlowerDynamicColorSource.Refresh` (RVA 0x2743CE0), `Tint0`, `Tint1`, `Tint2`, `MaskRef`, and `DynamicColorViewBase.RefreshMaterial` / `ModifyMesh` / `AdjustMaskOuterUV`. The v3.0.1 native Refresh implementation was inspected. The plucked state (6) is the dynamic-color branch; other growth states retain the initialized white tints and null mask. For a resolved flower visual model, a null pattern sets all three tints to the base color; a non-null pattern sets Tint0 and Tint2 to the base color and Tint1 to the resolved pattern color (white if absent). The mask lookup prefers the matching Pattern reference, then the null Pattern entry. These are display inputs, not mutation rules or a proof of valid unique-data combinations. The shared shader implementation and source-derived runtime are described below. Full in-game image parity remains unverified. No mutation logic is added. The existing Rust/WASM unique-data read path remains authoritative.

Native evidence: Switch main SHA-256 64bd5fb69239f57eb0578a1897a45a3c6f5e187480903f83df503b46bf827bfb; Refresh code RVA 0x2743CE0–0x2744240, SHA-256 dd2de968afd04bb22d2b75aff7a5c60baaefb03ccd85dcfa5c938beb165af873. The separate dynamic-icon inventory in `data/unityfs-audit/dynamic-uiicons.v3.0.1.json` records all 50 flagged definitions, not a completed-render allowlist. Flowers use per-pattern masks rather than the generic definition mask.

## Shared sprite shader recovered

The Steam inventory prefab contains ten DynamicColorView components referencing the same original material (fileID 5, PathID -4345124125649775645). Its external CAB resolves to `shaders_alwaysloaded`; material `DynamicSpriteColor` references `Sunblink/UI/Dynamic Sprite Color`. Inspection of its non-clipped pixel program establishes sequential RGB interpolation: start at white; interpolate toward Tint0 by mask R, Tint1 by mask G, then Tint2 by mask B. Multiply the resulting RGB (alpha 1) by the vertex color and sampled base RGBA plus texture sample add. Mask alpha and tint alpha do not select a tint. Switch `AdjustMaskOuterUV` maps source outer UV relative to source inner UV into the mask inner UV range. Both math functions and on-demand sample composition now exist in `src/dynamic-sprite-color.ts`; source-verified flower tint/mask selection is in `src/flower-appearance.ts` (conservatively excludes unsupported pattern/growth values). These are presentation-only, not save mutation rules.

All 25 flower base tiles were independently reconstructed from original GlobalUIAtlas Sprite render rectangles (256 logical pixels, rounded trim crop, Lanczos to 84 pixels with 6-pixel padding) and compared with the actual published CI site's original base packs: 25/25 alpha planes match exactly. 23 tiles are in the flowers pack, one each in City Town and Wheatflour Wonderland. RGB was not asserted equal, and these are not final dynamic render comparisons. Exact per-item geometry and source evidence are in `data/unityfs-audit/dynamic-sprite-color.v3.0.1.json`. No raw shader binary or generated variants are published.

Historical boundary before PR #127: the sample compositor was not yet wired into the inventory. See the on-demand runtime below. 

## On-demand runtime (v3.0.1)

The former 96px species tiles were rechecked against the decoded native crops: 25/25 alpha planes matched, but 0/25 RGB planes were byte-identical. They are retained only as species fallback. The runtime therefore uses the original, unresampled base texels and a one-texel bilinear guard, with opaque RGB and separate linear alpha planes in `flower-base-source-v3.0.1.webp`. The RGB-only `flower-mask-rgb-v3.0.1.webp` preserves all mask color values (463,808 source pixels have nonzero RGB at zero alpha); mask alpha is not read by the recovered shader. Both lossless WebP assets have exact decoded RGB readback hashes in the runtime manifest. No individual color/pattern variant is pregenerated. The original full RGBA mask remains archived in the repository pending migration verification.

Steam PlayerSettings in globalgamemanagers (SHA-256 df5020fcfdd7f6d0b8ccf15a80d4231a421aa23ccb79c7e394c1fb8adca043d4), class 129 PathID 1, m_ActiveColorSpace at offset 284 = 1 (Linear). The matching Unity 6000.0.78f1 release field layout is documented in AssetRipper/TypeTreeDumps. Native base and mask Texture2D: m_ColorSpace=1, m_FilterMode=1, wrap U/V/W=1, mipCount=1. Base Sprite borders are zero, render settings 67, downscale 1; mask borders zero, settings 65, downscale 1, no rotation. Switch DynamicColorViewBase.ModifyMesh RVA 0x2CDD270 (SHA-256 c08fcb7953c401ff2ad99cbbc43c960648f84f5ceba6b4aa2f3d2b5e56db6a2a) obtains source outer/inner UV and mask inner UV; GetDrawingDimensions RVA 0x2CDCB50 (SHA-256 e6b0f822ff7c2fb5d52906ea2aa060a400b0a5fd1b2dc9686f2b49663e736a0c) uses trim geometry. For the verified zero-border non-rotated path the inner and outer UVs coincide. The runtime samples the exact fractional source rect and corresponding mask rect, decodes RGB to linear before bilinear interpolation, converts Color tints under standard Unity linear-color semantics, executes the recovered shader and encodes output to sRGB. The 96px card geometry is an editor UI choice. Framebuffer/Unity GPU precision and final in-game screenshots have not yet been compared; the DOM marks this as source-derived-runtime, not a verified game capture.

Only v3.0.1 plucked state (6) with known colors and known pattern definitions is enabled. Explicit masks take precedence; the native default-mask branch supports other known patterns, including effects. Unknown patterns/colors, missing assets or unsupported states retain the species fallback and existing indicators. The renderer is read-only, lazily loads hash-verified source assets, and uses a bounded 192-entry promise/Blob cache keyed by appearance, not document identity. No changes to Rust save mutation rules. Canvas-generated PNG blobs are local and their object URLs are revoked on replacement/unmount.

## Native UI effect-mask fallback

Re-examination of the pinned Switch main confirms that FlowerDynamicColorSource.Refresh (0x2743CE0) branches on null Pattern, not on FlowerPatternDefinition.IsEffect (offset 0x40). Its matching predicate at 0x2744250 compares Pattern references; the fallback predicate at 0x2744390 accepts null (also checks the game's default sentinel). The original Steam manifest contains a null-pattern mask for all 25 flowers. The eight effect indices (3 Cosmic, 4 Crystal, 5 Frost, 6 Glitter, 7 Glow, 8 Iridescent, 9 Molten, 15 Sunbeam) have zero dedicated UI masks. These effects use the source-derived fallback rather than invented glitter, glow, or 3D surface shading. The existing pattern/effect sprite and color indicators remain. InventoryItemDecoratorCollection.PendingChanges.AddFlowerIcons (0x378C4E0) references the original FlowerColorDefinition.Color and FlowerPatternDefinition.Icon separately. This is the inventory's 2D icon path, not the flower's world material.

## Growth-state display boundary

Native tag-7 states 0 (Seed), 6 (Plucked), and 7 (GrownTroweled) are distinct inventory records even with identical species/color/pattern. The existing extracted 25 species sprites and masks support the plucked branch only. Species-reference art for non-plucked states is not a state-specific sprite, and the editor must not apply the plucked shader to those states. The inventory adds concise localized editor state descriptions to variant labels and search, and marks non-plucked artwork as a species reference. The species ID list is checked against the pinned flower definition projection; tag-7 crafted clothing is not described as a seed/plant. Other state values are not guessed. Exact native growth-state sprite selection, associated localized game strings and assets remain to be recovered. No save fields or mutation permissions are changed.
