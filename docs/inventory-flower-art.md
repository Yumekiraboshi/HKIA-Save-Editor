# Native dynamic flower artwork — Steam v3.0.1

The inventory flower art pipeline uses the original `FlowerItemDetails.PatternMasks`, not similarity, species-name matching, or a generic petal mask. `public/inventory-flower-art/index.json` maps the native Item ID, native pattern index and AssetReferenceSprite GUID to the exact Sprite path ID and original atlas render data. Twenty-five flower definitions have 161 distinct mask references, all resolved against the original `atlas_iconcolormasks` AssetBundle.m_Container GUID keys. Pattern index 0 in this mapping denotes the original null Pattern reference, not an editable flower pattern. No valid-option or entitlement claims are made.

Source hashes are pinned in the index. The original atlas Texture2D (CAB-4b1eea545f0ffab2c4bbd5e5b64d20b0, PathID 7743984056776833729) was decoded from BC3 and vertically oriented, then encoded at its original 2048×2048 size as VP8L method 6 with exact decoded RGBA readback. The WebP contains the source atlas, including ten non-flower masks; it is not fetched by the current inventory UI. No original UnityFS bundles are included.

Switch v3.0.1 type definitions identify `FlowerDynamicColorSource.Refresh` (RVA 0x2743CE0), `Tint0`, `Tint1`, `Tint2`, `MaskRef`, and `DynamicColorViewBase.RefreshMaterial` / `ModifyMesh` / `AdjustMaskOuterUV`. The v3.0.1 native Refresh implementation was inspected. The plucked state (6) is the dynamic-color branch; other growth states retain the initialized white tints and null mask. For a resolved flower visual model, a null pattern sets all three tints to the base color; a non-null pattern sets Tint0 and Tint2 to the base color and Tint1 to the resolved pattern color (white if absent). The mask lookup prefers the matching Pattern reference, then the null Pattern entry. These are display inputs, not mutation rules or a proof of valid unique-data combinations. Source material binding, shader arithmetic, effect handling and complete growth-state icon selection still need verification. The mask atlas is exact source art; a final flower composite is not yet implemented or claimed exact. No mutation logic is added. The existing Rust/WASM unique-data read path remains authoritative.

Flowers use per-pattern masks rather than the generic definition mask.
