# Native furniture mesh upload and offline surface GPU diagnostic

`src/native-furniture-mesh.ts` consumes the exact original static mesh metadata and packed geometry, validates whole-file and per-stream SHA-256, original interleaved stride/channel formats, non-overlapping ranges, finite float32/float16 attributes, original uint16 triangle index bounds and signed PathID identity. It uses native WebGL2 FLOAT/HALF_FLOAT/normalized UNSIGNED_BYTE attributes and explicit caller-supplied shader attribute locations, without synthesizing missing UVs. Failed uploads clean up VAOs/buffers and restore bindings; successful uploads have explicit disposal. No raw geometry, original bundle, texture stream, save data or completed variants are committed.

Optional offline diagnostic: `xvfb-run -a python scripts/furniture-surface-gpu-smoke.py --mesh-dir <local-geometry-staging> --base-dir <local-base-texture-staging> --pattern-dir <local-pattern-staging> --chromium /usr/bin/chromium --headed --swiftshader` (requires original extracted assets, Python Playwright and TypeScript; preview camera metadata from PR #149). This is a development smoke, not an additional required CI job. It compiles the production transport primitives, transfers all 11 mesh streams (162644 bytes) and 19 original textures (4544196 bytes) into an actual Chromium WebGL2 context, draws all six original rug material definitions (207–212) on the original mesh with original UV channels and extracts 512x512 RGBA pixels. The local run completed successfully twice, each with 18454 nontransparent pixels per variant and six distinct frame hashes. The test uses SwiftShader software GPU under Xvfb; headless Chromium previously could not initialize the GPU. A local about:blank canvas uses a host SHA-256 callback only because it is not a secure origin; no production hash verification is bypassed or changed. No network, user save, or Pages deployment is used by this diagnostic.

The diagnostic is deliberately surface/albedo only: it applies the source UV and color mix, uses the prefab camera relative to its rig and a diagnostic mount-spawn position/scale fit. The actual mount attachment/rotation, runtime light context, final shader variant, color transform, reflection, shadow, post-processing and native framebuffer parity are not verified. BC1 RGB is explicitly selected for this diagnostic; not a general proof of runtime alpha semantics. No diagnostic images are published in the production editor, and no completed icon or exact fidelity is claimed. This prefab has a mesh/material and three GameObjects/transforms but no Light; the surrounding interior scene RenderSettings and AreaLightUpdater are separate and do not alone prove the local preview lighting parameters. Do not infer lighting from the static item sprite.
