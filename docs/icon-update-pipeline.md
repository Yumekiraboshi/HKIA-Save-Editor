# One-command native icon update

Use the original game bundles and the same-version candidate shared collection catalog. Review the native layouts first; the input file is an explicit assertion of that review, not an automatic compatibility guess. Keep all originals and candidate outputs outside the repository.

Example local input (replace paths and hashes with actual original SHA-256 values):

```json
{
  "schema": "HKIA.IconUpdateInput.1",
  "version": "3.0.1",
  "platform": "steam",
  "reviewedLayouts": {
    "outfit": "outfit-icon-override-v1",
    "atlas": "unity-v22-uiicon-v1",
    "dynamic": "native-dynamic-v1",
    "auxiliary": "native-icon-auxiliary-v1",
    "result": "native-result-icon-v1"
  },
  "bundles": [
    {"name":"definitions","file":"original/definitions.bundle","sha256":"<actual sha256>"},
    {"name":"atlas_global","file":"original/atlas_global.bundle","sha256":"<actual sha256>"}
  ],
  "overrideBundles": ["definitions"],
  "catalog": {"file":"candidate-catalog.json","sha256":"<actual sha256>"}
}
```

Include all actual base/mask/override/auxiliary bundles, not just the example two. `overrideBundles` selects actual completed-image containers; `overrideDefinitions` optionally specifies an explicitly reviewed separate platform definition bundle (platform/file/sha256). Cross-platform ID/key/GUID closure is checked by the existing assembler. Add the reviewed original swatch layout described in [auxiliary assets](icon-auxiliary-assets.md) when the dye configuration is available. Missing source data is never substituted with guessed or previous-version artwork.

```sh
python scripts/update-icon-release.py --input release-input.json --out /staging/3.0.1-candidate
python scripts/update-icon-release.py --input next-input.json --out /staging/next-candidate --previous-run /staging/3.0.1-candidate
# After an interrupted command, repeat the exact invocation with --resume.
```

The command fingerprints the provided originals/catalog, checks the reviewed source layouts, runs each existing extraction/assembly script, and atomically commits completed stage directories with content digests. Resume verifies the exact run input and implementation identity, dependency digests and every retained stage file; changed code/input requires a fresh run. Previous-run reuse uses validated previous-stage receipts and the existing source-identity checks. No original or live public file is changed. Stage subprocesses release large decoded bundles between stages. The final summary is steps/summary/candidate.json; it links the generated release, auxiliary pages and family manifest and lists source blockers. This is intentionally a review-only candidate, not automatic publishing. All original definition UiIcon PPtrs are staged for wand overlays, with shared lossless guarded source pages and rectangular logical geometry. The summary reports unresolved original UiIcon IDs separately from inventory main icon routes. This does not change wand ingredient eligibility. Full-source staging size and actual candidate browser/game behavior require measurement before release; source-specific decorators also remain to be verified.


## Owner-approved original resolution migration (2026-11-28)

The current one-command candidate pipeline uses `native-resolution-lossless-webp-v1`. It calls the same original definition and completed override extractors with `--native-resolution`, assembles content-addressed native WebPs in `native-art/` with independent base/override/collection routes, and reuses the existing guarded original dynamic source pages and native result selection. No normalized collection or inventory image sheets are generated by this new candidate path. The individual legacy scripts retain their existing mode for the still-published release and old regression tests; never use resized legacy stage data as input to a native candidate.

The shared original-resolution encoder verifies exact decoded RGB/RGBA, VP8L and dimensions (including fully transparent RGB where the decoder supplies it). It uses the original rounded logical canvas/trim geometry of the reviewed Sprite extractor without resampling; fractional Sprite render coordinates are retained in source bindings and this is not a claim of Unity framebuffer parity. Dynamic source pages retain their raw guarded texels and mask color spaces. The same shader rasterizer can render with the original logical width/height and no normalized margin, using lossless PNG locally; the candidate service requires both source pins to request native output. Static artwork is lazily retrieved and deduplicated by digest; the initial candidate uses individual immutable WebPs rather than fixed cells. Cache bounds are provisional and need real workload measurement.

The candidate summary reports native static asset count, unique native image bytes, release transport bytes and auxiliary page bytes. These are partial transport measurements, not the complete game's asset budget until all view/decorator images are migrated. The existing production UI and delivery paths remain unchanged pending original-source extraction and verification. Achievement/category stages now use the same original Sprite staging and native encoder; the remaining decorator sources, dynamic source page size limits and full-source route verification still need review. Source-compressed textures remain decoded originals, not restored pre-compression pixels. No hosting change or production activation.


### Original-resolution view art and delivery root

Supply optional fingerprinted `achievementArt` (census, index, hierarchy) and `categoryArt` (census, scope) input objects, using the existing file/SHA-256 shape. Original pointers still require a reviewed census. Both stages use the same original Sprite/texture/trim decoder, lossless encoder and prior source fingerprint reuse. Their manifests are `HKIA.AchievementArtCandidate.2` and `HKIA.CategoryArtCandidate.2`, referencing original-size assets instead of cells. The distribution stage emits one content-addressed `native-art/` directory for all static item/category/achievement images, plus original dynamic and auxiliary source pages, family bindings, receipt and view manifests. Do not publish the individual stage checkpoint directories. `createNativeArtService` composes all three tool readers with a shared bounded native-image loader; exact view pins must agree with the original item definition and platform. The summary reports deduplicated static image count/bytes and distribution bytes, and lists omitted or unresolved view inputs separately. The original `FlowerPatternDefinition.Icon` PPtr is included in the auxiliary source stages. Other contextual decorators/plate assets and original pointer-census extraction remain outstanding. Live UI is unchanged until source and browser validation.
