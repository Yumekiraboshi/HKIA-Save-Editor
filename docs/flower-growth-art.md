# Flower growth-state inventory icons (Steam v3.0.1)

The original definitions and GlobalUIAtlas fingerprints are pinned in public/inventory-flower-art/flower-growth-source-v3.0.1.json. All 25 FlowerItemDetails definitions reference distinct original SeedIcon and GrownTroweledIcon Sprite objects. The final two original PPtrs precede RandomYRotation and RandomUniformScale (16 bytes); all 50 resolve locally in definitions, then through the original SpriteAtlas PPtr and exact 24-byte m_RenderDataKey. All resolve to 25 original BC3 2048x2048 single-mip Texture2Ds in atlas_global, with no missing keys or inferred image identity. Names, PathIDs (strings), logical bounds, texture rects, offsets, object and crop SHA-256 values are retained in the source manifest. These art bindings are display-only and do not change legal save states.

State 0 selects SeedIcon; state 7 selects GrownTroweledIcon. State 6 retains the verified native plucked-flower dynamic color path. Unknown states do not select a growth icon; original representative species art remains explicitly marked as fallback. Flower creation clothing/candles are not plant species. See docs/flower-native-icon-route.md and docs/inventory-flower-art.md for executable dispatch evidence.

Local extraction used the original byte streams and a type-tree reader equivalent to the existing helpers. Exact source crop restored to the original 256x256 logical tile, Lanczos resized to 84x84 with 6px margin in a 96px cell, same display convention as other inventory packs. Pillow 12.3.0, WebP lossless method 6, sheet 960x480, 306216 bytes; all 50 nonempty, visible RGBA and alpha identical to pre-encoding resized sheet. This is a native source image at editor thumbnail resolution, not a claim of bitwise parity to the game's framebuffer. The canonical extraction script is included but has not independently been run. The exact WebP payload is published as a binary file, replacing the older 408,289-byte base64 transport with the same verified 306,216-byte image (102,073 bytes smaller). Runtime verifies source and image byte hashes directly, checks image dimensions and uses one page-lifetime object URL shared by every seed and troweled card. No base64 decoding or duplicate encoded buffer is needed. No variant combinations are pregenerated. The same Svelte component handles inventory and edit preview. No game bundle or player save is published. No new save mutation code.

Reproduce with `python scripts/extract-flower-growth-art.py --root /path/to/source-copies --out /path/to/staging` (definitions.bin and atlas_global.bin, pinned source version). Future game updates must regenerate both the manifest and sheet, and update source fingerprints and coverage tests.
