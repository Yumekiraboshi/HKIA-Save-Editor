# Furniture customization source — Steam/Switch v3.0.1

`public/inventory-ui/furniture-customization-v3.0.1.json` is a source-derived catalog, not a save writer or entitlement grant. The original Steam definitions CAB contains `LynxMrdPayload` PathID -7028284721756550088. Its serialized FurnitureMaterialData list starts at byte 142568 (877 rows); FurnitureMaterialStoreData follows at 350720 (780 rows). All 877 non-null enum names/indices were cross-checked with the Switch v3.0.1 IL2CPP definitions. All store GUIDs resolve. Four source materials have explicit PatternUnlockItem references, resolved by original Item ID; these are not automatically granted.

141 original FurnitureMaterialDefinitionSet objects contain 1046 ordered material references, all resolved by GUID. The exact item definitions for FurnitureItemDetails (1637) and HomeCustomizeItemDetails (197) were walked to their serialized ends, with no unresolved slot, material, default or set references. 621 furniture and 28 home-layout item definitions are customizable. The nine source defaults outside AllowedSets remain distinct from selectable materials. PlayerHomeExteriorItemDetails is a separate layout, excluded here; this does not imply exterior items are unsupported in the game or alter confirmed product scope.

The material rows retain original store UI color values and icon GUIDs, not a verified rendered pattern image. Source slot labels and enum names are internal metadata, not localized game item names. No genuine player data, original game bundle or pre-rendered combinations are included.

FurnitureUniqueDataV2.ResolveIndex (0x332B680) and ResolveGuid (0x332B4D0) use FurnitureMaterialDatabase. Source data alone does not authorize a mutation: default/null handling, identity/collision, placement/reference and unlock applicability must be enforced by the existing Rust editor. The generated Rust lookup is compile-time source data only. The existing product goal is unchanged.

## Original 3D visual references for on-demand rendering

The source-only `data/furniture-visual-source-v3.0.1.json` crosswalk is keyed by the same Item IDs and definition PathIDs as the existing furniture customization catalog. The original Steam definitions SHA-256 is pinned; `scripts/extract-furniture-visual-source.py` reads the serialized InventoryItemDefinitionAsset base Sprite PPtr, Visual3D AssetReference and managed FurnitureItemDetails / HomeCustomizeItemDetails Prototype or AssetSet and Customizer3DVisual AssetReferences. All 649 customizable definitions have a non-null Visual3D and prototype/asset-set GUID, and 44 furniture definitions have an explicit separate customizer visual. All 649 original UiIcon references resolve to Sprite objects (648 distinct Sprite identities); none uses the UiIconUsesDynamicColor flag or mask reference. Thus the dynamic 2D color-mask pipeline for flowers cannot be presumed to apply to furniture. A normal inventory tile's original icon and the customized 3D preview are distinct concepts. The original v3.0.1 IL2CPP FurnitureCustomizerItemPreview.GetCustomizer3DVisual (0x36699C0), ApplyMaterials (0x366A1B0) and UpdateItemMaterials (0x3668520) provide the native preview route; its complete fallback selection, prefab dependencies, renderer slot mapping, camera, lighting and shader fidelity still need verification. This map does not select a substitute model, render a variant, or grant write eligibility. No completed variant images or original bundles are published.
