# Furniture customization source — Steam/Switch v3.0.1

`public/inventory-ui/furniture-customization-v3.0.1.json` is a source-derived catalog, not a save writer or entitlement grant. The original Steam definitions CAB contains `LynxMrdPayload` PathID -7028284721756550088. Its serialized FurnitureMaterialData list starts at byte 142568 (877 rows); FurnitureMaterialStoreData follows at 350720 (780 rows). All 877 non-null enum names/indices were cross-checked with the Switch v3.0.1 IL2CPP definitions. All store GUIDs resolve. Four source materials have explicit PatternUnlockItem references, resolved by original Item ID; these are not automatically granted.

141 original FurnitureMaterialDefinitionSet objects contain 1046 ordered material references, all resolved by GUID. The exact item definitions for FurnitureItemDetails (1637) and HomeCustomizeItemDetails (197) were walked to their serialized ends, with no unresolved slot, material, default or set references. 621 furniture and 28 home-layout item definitions are customizable. The nine source defaults outside AllowedSets remain distinct from selectable materials. PlayerHomeExteriorItemDetails is a separate layout, excluded here; this does not imply exterior items are unsupported in the game or alter confirmed product scope.

The material rows retain original store UI color values and icon GUIDs, not a verified rendered pattern image. Source slot labels and enum names are internal metadata, not localized game item names. No genuine player data, original game bundle or pre-rendered combinations are included.

Switch source: FurnitureCustomizationHelper.IsValidCustomization (0x3A5CAF0) checks the ICustomizeItemDetails flag and validates all three slot assignments with IsMaterialValidForItem (0x3A5CDC0). FurnitureUniqueDataV2.ResolveIndex (0x332B680) and ResolveGuid (0x332B4D0) use FurnitureMaterialDatabase. Source data alone does not authorize a mutation: default/null handling, identity/collision, placement/reference and unlock applicability must be enforced by the existing Rust editor. The generated Rust lookup is compile-time source data only. The existing product goal is unchanged.

## Original 3D visual references for on-demand rendering

The source-only `data/furniture-visual-source-v3.0.1.json` crosswalk is keyed by the same Item IDs and definition PathIDs as the existing furniture customization catalog. The original Steam definitions SHA-256 is pinned; `scripts/extract-furniture-visual-source.py` reads the serialized InventoryItemDefinitionAsset base Sprite PPtr, Visual3D AssetReference and managed FurnitureItemDetails / HomeCustomizeItemDetails Prototype or AssetSet and Customizer3DVisual AssetReferences. All 649 customizable definitions have a non-null Visual3D and prototype/asset-set GUID, and 44 furniture definitions have an explicit separate customizer visual. All 649 original UiIcon references resolve to Sprite objects (648 distinct Sprite identities); none uses the UiIconUsesDynamicColor flag or mask reference. Thus the dynamic 2D color-mask pipeline for flowers cannot be presumed to apply to furniture. A normal inventory tile's original icon and the customized 3D preview are distinct concepts. The original v3.0.1 IL2CPP FurnitureCustomizerItemPreview.GetCustomizer3DVisual (0x36699C0), ApplyMaterials (0x366A1B0) and UpdateItemMaterials (0x3668520) provide the native preview route; its complete fallback selection, prefab dependencies, renderer slot mapping, camera, lighting and shader fidelity still need verification. This map does not select a substitute model, render a variant, or grant write eligibility. No completed variant images or original bundles are published. SHA-256 of extracted JSON: 0d42521f81b7f8a0a295a8e3c9d0c6ca713d5b34ad572517a7ddf3118293a691.

### Static mesh and renderer-slot extraction

`scripts/extract-furniture-mesh-source.py` consumes the source visual and Addressables maps and an original local UnityFS bundle. The exact AssetBundle container GUID selects a single GameObject, not a visually similar prefab. The Unity serialized type tree supplies object field boundaries. The extractor walks local Transform children, checks parent/owner references, pairs MeshFilter and MeshRenderer, and reads the original CustomizableFurnitureVisual.VisualSlots (renderer PPtr, SlotAssignment 0/1/2, displayed-definition reference). The script PPtr is external CAB-2383a36f15413272ed26f383f73f6431, PathID -4647883882007958521; the source type tree contains VisualSlots, CustomizedPreviewId and DefaultMaterialIsValid matching v3.0.1 IL2CPP metadata. It rejects ambiguous roots, unsupported mesh formats, external meshes, multiple submeshes/materials, invalid indices, and unsupported vertex layouts. It does not assume a mesh name determines a slot. Non-customizable renderers are retained separately.

Original local test samples (four exact Visual3D GUIDs): Item 32709745 (COLO26 rug: one slot), 34770598 (JAMJ24 stand: three slots), 61381969 (antique desk lamp: two slots), 90163601 (scholastic chair: two slots). All four roots yielded a complete local transform tree with 11 unique static meshes, exact 16-bit triangle indices and streamed interleaved vertex channels (float32 positions; source half-float and UNorm channels preserved, including vertex colors where present). Packed geometry totals 162644 bytes, output SHA-256 and per-stream byte ranges recorded in `data/furniture-mesh-source-sample-v3.0.1.json` (SHA-256 161428cccd58c9737e133ac60a128744a94672b4606c84d8f2a0bd696a923f70). Geometry bytes are offline staging outputs, not published models. Original shader PPtrs and external/local base Material references are retained. Runtime material property application, pattern textures, camera and lighting, and native icon vs preview differences are not yet resolved; no rendered variant is exposed. Four samples are not complete coverage. The CLI is currently limited to this static mesh layout and chooses explicit Customizer3DVisual when present, otherwise Visual3D as an extraction candidate; this is not yet a proof of native fallback behavior for every item.
